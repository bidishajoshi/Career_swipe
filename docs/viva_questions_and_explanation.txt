Concise Project Explanation — How CareerSwipe works

Overview
CareerSwipe is a monolithic Flask web application that connects job seekers and companies. It stores users (seekers/companies), job listings, and application swipes in a relational database using SQLAlchemy. The UI is rendered using Jinja2 templates and styles in `static/css`.

Entry points
- `apps.create_app()` (factory) builds the Flask app with Blueprints for modular routes.
- `wsgi.py` or `app.py` are used to run the app in different modes.

Key flows
- Seeker: register → upload resume → swipe or apply to jobs → system computes match & ATS scores → application (JobSwipe) created → company notified.
- Company: register → post job → view applicants → update applicant status (shortlist/interview/accept/reject) → optional email notifications sent.

Scoring & Resume parsing
- `utils/resume_parser.py` extracts text from uploaded resumes.
- `utils/tfidf.py` computes TF-IDF style similarity between resume text and job text to produce match scores. An ATS heuristic function produces an ATS score.

Notifications & Email
- In-app `Notification` records are created via `apps/services/notification_service.py`.
- Emails are sent using the configured mail extension; `apps/services/email_service.py` prepares HTML emails.

Uploads & Static
- Uploaded files are saved to configured folders (e.g., `RESUME_FOLDER`, `LOGO_FOLDER`). Static route handlers normalize paths so `url_for('static', filename=...)` works.

Security
- Passwords hashed with Werkzeug.
- Simple session-based auth for companies and seekers.
- CSRF protection via Flask-WTF where available; some API endpoints exempted.

Where to read code
- Routes: `apps/routes/` (auth, seeker, company, jobs, profile, notifications)
- Models: `apps/models/`
- Services: `apps/services/`
- Utilities: `utils/`
- Templates: `templates/`
- Static CSS/JS: `static/`
